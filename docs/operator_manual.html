What the tool does

Geometry

Uses 3D wires and POA markers to derive circuit-level 2D wires, 3D structure points and Caydence deliverables.

Other selected products

Optionally creates AOI-clipped LiDAR, PLS XYZ, tile index and management units outputs, depending on product selection.

01 / Before you start

Keep the package in its own directory

Do not overwrite a previous tester version. The folder should contain run_eversource.bat, setup_eversource.bat, input, output, source and scripts.

Install dependencies once

Run setup_eversource.bat. This creates the Python environment under scripts\.venv. Do not edit files inside the scripts folder.

Verify source data is available

The GUI uses its packaged source folder. Ensure the required project source files are present. The SoW SQLite provides circuit reference geometry, but does not replace client structures or the 3D DXF data.

Version checkThe GUI title, the GUI header and the run log show the full build label, e.g. R01.05-test build 20261119b (commit 6807c1e). Every stage also prints a [BAKERY] … line, and every QA_RUN_MANIFEST.json records the build and full commit under "bakery". Always quote this label when you report results. A label ending in -dirty or showing unknown is not an official package.

02 / Workspace and inputs

GUI controlWhat to choose
Input FolderDirectory containing the actual project inputs. The preflight inspects available DXF contents to identify 3D wires and POA markers; do not rely only on filenames.
Source FolderFixed package reference folder; displayed as read-only in the GUI. Contains project-wide references.
Output FolderA new, empty folder for each cluster. The tool does not clear old results: RoW folders from a previous cluster stay there and can be delivered by mistake. If two clusters share a RoW, the second run overwrites the first one's deliverables for that RoW.
Project CRSCheck the EPSG suggested from AOI .prj. For CT: EPSG:6434. If changing a detected CRS, confirm the override deliberately.
Capture yearYear used in deliverable naming, e.g. 2026.
WorkersParallel workers. In Geometry they sample LiDAR tiles in parallel, and the log shows progress (tiles done / total, ETA). A good value is the number of CPU cores minus 1.
Product SelectionSelect Geometry for 2D wires and structures. Other products can be enabled independently as needed.
Input examplesFor the CT_17 / CT_33 test, the observed DXF inventory included Wires.dxf (3,026 3D line entities) and POA.dxf (558 point-like entities). These are dataset-specific figures, not expected counts for every run.

03 / Run a batch

Launch the GUI

Double-click run_eversource.bat. Check the displayed version, input/output paths, CRS, year, workers and selected products.

Press Start Batch

The application begins PREHEATING. It checks project inputs, reference data, CRS and RoW coverage. Review any low-coverage or missing-data flags instead of assuming every RoW is ready.

Select the RoWs

After preflight, choose the required READY RoWs in the selector (for example CT_17 and CT_33) and press Continue Batch. Only the selected RoWs proceed.

Monitor processing

MIXING builds geometry and Caydence products. If selected, BAKING / ICING / PACKING builds point-cloud and additional products. Monitor log messages; a successful intermediate stage does not mean the entire batch has completed.

Open Deliverables and QA

Use the GUI's Open Deliverables and Open QA controls. Do not publish output solely because the run completed; perform the visual checks below.

[BAKERY] R01.05-test build 20261119b (commit 6807c1e)
EVERSOURCE TESTER R01.05-test - 01 GEOMETRY
Selected RoWs: CT_17, CT_33
...
Geometry deliverables: ...\deliverables
[Confirm the batch finishes without ERROR before accepting the result]

05 / Visual QA in QGIS

Check circuit continuity

Inspect adjacent spans and look for isolated circuit switches within a continuous conductor path. Do not automatically assume every even conductor count must split equally.

Check structure completeness

Where there are real POA markers, the corresponding physical structure should be represented, even if its source record is missing.

Minimum QA checklist

CheckPass condition
CircuitsNo unsupported single-span circuit swaps or cross-circuit merging.
POA / structuresExisting POA-supported structures retained; dummy used only when source matching fails.
Shared structuresOne physical XY with separate circuit records where source confirms shared ownership.
DCWPPosition follows the confirmed middle member; source XY is a candidate fallback requiring review.
Terminal wires2D represents real terminal 3D conductors even without terminal POA.
SubstationsNo invented terminal structures without physical POA/source evidence.
Logs / exportsNo final ERROR; all expected SHP/GPKG components readable in QGIS.

06 / Understanding the geometry rules

POA present, source missing

Create a dummy structure using the physical POA-derived position. Preserve the formal output schema; fields mapped from source remain NULL.

3D wire reaches into substation

Generate terminal 2D from measured/vectorised 3D wires. No POA at the far endpoint is required, and no artificial structure is added.

Caydence PHASE and EARTH QA (since R01.02/R01.04)Geometry samples source LiDAR class 187 (Tx Conductors) and class 210 (Tx Shield Wires) alongside the ground class. When enough classified 3D points consistently match a DXF conductor, Caydence assigns PHASE or EARTH without waiting for PLS XYZ exports. Open 01_caydence_lidar_wire_roles.csv and review any INSUFFICIENT_LIDAR entries before delivery. Correctly classified DXF levels are preserved.
SCHF/SCSH geometry (since R01.04)When three parallel phase wires are clearly identified on an SCHF H-frame or an SCSH with one nearby original Tower Top, the representative structure point is moved perpendicular to the route onto the middle PHASE wire. Ground height is resampled. Ambiguous cases remain unchanged and are recorded in 01_structure_middle_phase_qa.csv.

07 / What changed in R01.05-test

AreaWhat you will see
PreflightResults are cached in output\00_preflight\00_cache and reused when the inputs have not changed, so a repeated run skips the long validation. To force a fresh preflight, use --no-cache or set BAKERY_NO_PREFLIGHT_CACHE=1.
2D circuit wireThe 2D wire represents the central phase of the circuit, and is never an EARTH wire. Duplicate copies of one conductor in the DXF are ignored for 2D. A short step (≈4 m) at a structure where horizontal phases change to a vertical arrangement is expected, because the middle of the circuit really moves there.
Parallel linesPOAs of two separate parallel lines are no longer merged into one structure in the middle (01_support_split_qa.csv).
SubstationsTerminal spans that turn sharply into a substation bay are recovered from the 3D wires (01_terminal_2d_recovery.csv).
RoW boundariesA RoW ends on a structure, never in the middle of a span. A structure at the start or end of two RoWs is written to both RoW deliverables. This is intended, so do not delete these duplicates (01_row_boundary_qa.csv).
Deliverables layoutOrganised by output product: 29_tile_index/<RoW>, 45_structure_shapefile/<Circuit>, 68_standalone_gis/<RoW>, 80_powerline_vectors/<Circuit> and 267_caydence_conductors/<RoW>. A circuit in two RoWs has one file, with one 2D feature per RoW (field ROW). When copying several clusters into the output products, merge files of a circuit that continues across clusters instead of overwriting them.
Caydence structures (267)One record per physical support. On a support shared by several circuits, CIRCUIT lists them all, e.g. 1500;1605. Product 45 keeps one structure per circuit (01_caydence_structure_dedupe_qa.csv).
TapsTaps (branches leaving the line part-way, e.g. into a substation) are added to the circuit 2D from the observed 3D wires (01_tap_2d_recovery.csv). A tap may start up to 30 m from its circuit's 2D; the connector length is CONNECT_M. Rejected candidates (REJECTED_FEW_WIRES, REJECTED_RUNS_ALONGSIDE, NOT_CONNECTED_TO_2D) are worth a look; add the wire by hand if it is a real tap.
Caydence wiresEach wire is published in the RoW of its circuit. Pieces that the DXF splits at a crossing stay with the line they run along. A wire is never given to a circuit of a different voltage than its DXF level (ATTR_METHOD: PARALLEL_BUNDLE, LAYER_CIRCUIT).
Structure source matchAn unmatched POA that is the only one between two matched structures takes the nearest source structure (SRC_MATCH = CORRIDOR_AMBIGUOUS_NEAREST, to review).

Naming DXF levels in MicroStation

The tool reads voltage, line tag and circuit from the level name. Where circuits overlap or cross, naming the levels removes the guesswork:

Level nameMeaning
Mainline_345kVVoltage only (minimum; always keep the voltage)
Mainline_1_115kV, Mainline_2_115kVTwo separate lines of the same voltage that cross or share a corridor
Mainline_391_345kVBest option: the circuit name is used directly for bundling, tracks, 2D and Caydence
Wires left on an unnamed level (e.g. 0) are tolerated, but should stay a small minority.

08 / Fix in the QA GeoPackage and re-export

Edit

Open output\01_geometry\01_eversource_geometry.gpkg in QGIS. Correct spans, structures or Caydence wires, including their CIRCUIT / ROW attributes, and save.

Re-export

In the GUI press Re-export from GPKG. Choose the RoWs to write (by default those selected in the Geometry run) and confirm. Geometry is not run again.

Check

The 45/80 folders of the affected circuits and the 267 folders of the selected RoWs are rebuilt from the edited GPKG, and the previous files are backed up. Features belonging to other RoWs are skipped and reported as ROW_NOT_EXPORTED.

python scripts\04_export_geometry_from_gpkg.py --output-root output --rows NH_02,NH_27
python scripts\04_export_geometry_from_gpkg.py --output-root output --list-rows

Command-line equivalent of the GUI button.

09 / Troubleshooting

What you seeWhat to check
RoW marked MISSING / LOW_COVERAGEConfirm AOI coverage, input tiles and required reference data. Select only RoWs that passed preflight.
Wrong EPSG or offset geometryCheck input/AOI/*_Polygon.prj, GUI Project CRS and 00_crs_selection.json.
Geometry finishes, then GPKG export failsConfirm the build label (GUI title / [BAKERY] log line). Save the last 30–50 console lines and QA location for review; do not assume outputs are complete.
Wrong circuit on a short wire segmentCompare same physical conductor before and after the span in QGIS, along with SoW geometry and POA circuit ownership.
Missing structureCheck raw POA, source structure proximity, final structure SHP and support QA. A missing source attribute should not suppress a real POA-supported structure.
2D stops early at substationOverlay 3D DXF. If 3D wires continue, record the affected circuit and terminal wires for review.
When reporting a problemInclude the build label, RoW/circuit, input and output folder, screenshot, affected IDs (if available) and the end of the run log. Avoid editing deliverables by hand before preserving the failing output.
